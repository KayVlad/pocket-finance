# Local Pocket

Run `npm run dev`, then open `http://localhost:5173`. Keep the server running while using the app. The local database persists in `.wrangler/state`; it is separate from the hosted app.

Sign in with the username and password supplied when the first admin was provisioned. The admin's Users button creates ordinary users, resets their passwords, and disables/enables their access. Disabling or resetting revokes that user's existing sessions. There is no public registration or token login. Settings contains accent colour and password controls. Accounts have separate transactions, categories and preferences.

Press `+` to add. Amount receives focus; Tab moves through description, category, date, spending checkboxes and note. Ctrl+Enter (or Command+Enter) saves; Escape closes. Space accepts confirmation dialogs, including deletion and backup restore, unless you are typing in a field or the confirm action is disabled. Empty category/month cells open the form directly. Filled cells show history, with a separate + button for adding. Double-click a filled category/month cell to copy its transactions into all later months of the same year. Existing cells are replaced; descriptions, notes and flags are copied, and dates clamp to the last day in shorter months. Repeating the fill replaces the same future cells rather than adding duplicates. Receipts belong to their original transactions and are not copied forward. Overwriting future entries removes their attached receipts.

Income, Emergency fund, Investments, Essential and Personal are fixed groups. Emergency fund shows its category rows and Fund balance; Taken from fund appears in the bottom summary. Each year has its own categories. An uninitialized year copies the most recent earlier year's setup; already initialized years are independent, including empty setups. Rename, move between groups and reorder under Categories. Deleting a category permanently removes its transactions only in that year. The first upgrade preserves existing entries and the categories they use.

Refunded is a full refund: the entry stays in history but contributes zero to totals. Emergency fund entries are contributions kept outside regular income, expenses and investments. New contributions reduce Left over for their month/year: income minus expenses minus investments minus contributions. The existing fund balance does not reduce Left over. Taken from emergency fund moves an expense's effect from the regular budget to the fund without deducting from Left over again. A refunded fund-funded expense restores the fund amount. Fund balances carry across years and accumulate through the selected month. Old investment entries named Emergency fund are moved to the new group once during upgrade.

Year/Month switches between the annual grid and a compact monthly grid; phones start in Month. Grey surfaces stay neutral, while highlighted rows use a darker version of the user's accent.

Settings includes CSV export and a complete JSON backup of all transaction years, yearly categories, flags, notes and accent. Restore validates the entire file before atomically replacing only the signed-in user's finance data. Login credentials and other accounts are excluded and unaffected. Restore supports up to 10,000 entries and 20 MB, including up to 10 MB of receipt photos; downloading a backup does not change finance data.

For a fresh local database, run `npm run db:setup`, then `npm run admin:create -- --username admin --name Admin`. These commands use the same local bindings and persistence directory as the app. The offline script prints a generated password and refuses to bootstrap when an admin already exists. For a legacy account, pass `--account-id <existing-id>` to preserve its transactions. Older databases whose migrations were applied manually need their migration history reconciled before using `db:setup`. Never run provisioning SQL against the hosted database by accident.

`node scripts/test-finance.mjs` creates its own disposable local admin and test users, verifies yearly inheritance/deletion, category editing, fund/refund calculations, backup/restore isolation, CSV escaping, session revocation and admin permissions, then removes only those test accounts. It never uses or resets the real admin password.

History opens all transactions across all years, with a switch back to the selected period/cell. Search matches descriptions, categories, notes, dates and receipt filenames. Sign and With receipt / No receipt / Both filters combine with search. Transactions with receipts use a distinct accent tint and show download links beside Edit.

New or existing entries can attach up to 8 JPG, PNG, WebP or GIF receipt photos, up to 5 MB each and 20 MB per upload. Receipt bytes persist in local R2 storage under `.wrangler/state`, while account-scoped metadata lives in D1. Downloads require the owning account. Receipt attachments and removals save with the transaction; a failed upload does not create or change it. Backups include photo bytes (version 2), and older version 1 backups still restore. The generated `0003` migration adds receipt metadata without changing existing finance data.
